# Shiftify website

Marketing page for Shiftify, the offline timesheet app, with a download
link for the macOS `.dmg`. React + TypeScript + Vite, deployed to GitHub Pages.

## Run

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # → dist/
```

## Deploy

Pushing to `main` builds and publishes the site
(`.github/workflows/deploy.yml`). One-time setup on GitHub: Settings → Pages →
Source: **GitHub Actions**.

## Releases (published automatically)

The Shiftify source repo is private and the `.dmg` (~230 MB) is too big to
commit, so each version ships as a **release on this repo**, published by the
app repo's release workflow when a version tag is pushed there
(`git tag v1.0.1 && git push origin v1.0.1` in `shiftify`; see its
`desktop/README.md` › Releases). Each release holds:

- `Shiftify.dmg`: what the download button serves;
- `Shiftify-mac.zip` and `latest.json` (signed): what the installed Mac app
  reads to update itself. Don't rename, edit or re-upload them by hand: the
  app rejects anything that doesn't match the signature.

The download button links to `releases/latest/download/Shiftify.dmg`, so it
always serves the newest release without a site change. The version and size
next to it are read from the GitHub API at page load. Owner, repo and asset
name live in `src/config.ts`.

## Screenshots and promo video

Everything in `public/media` (and the full-size slides in `marketing/slides`,
2880×1800 for the Mac App Store) is generated by `capture/`, from Shiftify's
real web build:

```bash
cd capture
npm install && npx playwright install chromium
node serve.mjs ../../shiftify/desktop/app 8091   # in another terminal
node capture.mjs    # enters demo data, saves raw screens + card positions → raw/
node slides.mjs     # marketing slides (slides.html) → marketing/ + public/media/slides
node promo.mjs      # 25 s motion promo (promo.html) → public/media/promo.mp4
```

`promo.mjs 3 12.5` renders stills at those seconds instead, for checking a
change to `promo.html`. The video is encoded with AVFoundation
(`encode.swift`), so it needs macOS but no ffmpeg.

## Privacy policy and Terms of use

`privacy.html` and `terms.html` show the app's own legal texts (the Mac app
version), copied from the shiftify repo into `src/legal/` (English and Romanian). After changing them
in the app, run `npm run sync:legal` here and commit.

## Languages

English and Romanian, with react-i18next. Site text lives in
`src/i18n/locales/{en,ro}.json` (same keys in both). Visitors get their
browser's language (Romanian for any `ro-*`, English otherwise) until they
pick one from the RO / EN menu in the top bar; that choice is remembered.
The legal pages use the app's own `en.ts` / `ro.ts` (see above), in the Mac
or Windows version for the visitor's computer.

## Styling

Tailwind CSS v4 (`@tailwindcss/vite`). `src/index.css` holds only the theme:
the app's colours as Tailwind colours (`bg-surface`, `text-muted`,
`bg-primary`…), with their dark-mode values, plus a few base rules and two
custom utilities (`bg-hero-glow`, `scrollbar-none`). Components use utility
classes; shared looks live in small components (`components/ui/`: Container,
Section, SectionTitle, Card) and `buttonStyles()`.
